## Findings (ranked)

### code/agent-tools/list-camera-agents-status-case-mismatch
- severity: high · confidence: high
- evidence: `agent/tools/list_camera_agents.ts:19` filters `status: { in: ['open', 'under_review'] }`; `prisma/schema.prisma:104` `status String @default("OPEN")`, `src/app/api/agent/cameras/route.ts:25` uses `'OPEN'`, `agent/tools/search_violations.ts:19` upper-cases ("DB lưu chữ HOA"). Test `camera-orchestration.test.ts:47-58` never asserts `openViolations`.
- impact: `openViolations` is 0 for every camera on SQLite and Postgres; the lead agent's main "which camera is busy" signal is constant.
- action: filter on `['OPEN', 'UNDER_REVIEW']` and assert `openViolations` with a seeded OPEN violation.

### tests/agent-hooks/use-ask-session-no-coverage
- severity: high · confidence: high
- evidence: `src/hooks/use-agent.ts` `useAskSession` (working/ended/90 s quiet timeout, submit debounce) has no test and no React runner exists in the repo; it now backs three surfaces (widget, `/agent`, modal tabs).
- impact: a regression in the state machine ships silently with 3× the previous blast radius.
- action: extract the pure `{working, ended}` decision (sentAt, events, now) into `src/lib` and unit-test it under `node --test`, as `chat-shape.ts` was; a full hook runner is a separate decision.

### code/agent-toolsets/orchestration-tools-leak-into-subject-bound-sessions
- severity: medium · confidence: high
- evidence: `agent/lib/toolsets.ts:27-28,37` keys orchestration on `kind` only, while `agent/lib/preamble.ts:55` keys the paragraph on `!opts.cameraId && kind`; `ask` is routinely subject-bound (`SubjectAgentPanel.tsx:50` from camera/violation/site modals; `agent/session.ts:92,107` sets `ctx.cameraId`). Test covers `violation.review`/`camera.instruction` only.
- impact: a camera-bound ask gets `dispatch_to_camera` without the instructions paragraph and can queue instructions for other cameras; a site-modal ask (cameraId null) is treated as the lead agent.
- action: gate on the same predicate as the preamble (`ctx.cameraId ? tools : [...tools, ...orchestration]`) and extend the test with `names('ask', CAM_A)`.

### tests/camera-orchestration/dispatch-merge-not-asserted
- severity: medium · confidence: high
- evidence: `dispatch_to_camera.ts` returns `replacedPending` from `scheduleTask`'s merge; the per-session-limit test dispatches to `CAM_A` repeatedly (each merges) but never asserts `replacedPending` or that exactly one pending `camera.instruction` row exists.
- impact: duplicate instruction tasks per camera, or a wrong `replacedPending`, would ship undetected despite the tool docstring promising replacement.
- action: dispatch twice with different instructions; assert `replacedPending === true` and `count(kind='camera.instruction', subjectId=CAM_A, finishedAt=null) === 1`.

### code/agent-tools/dispatch-orphans-task-when-memory-write-conflicts
- severity: low · confidence: high
- evidence: `agent/tools/dispatch_to_camera.ts:33-36` — `scheduleTask` runs before `rememberCamera`, which throws after two CAS conflicts (`camera-agent.ts:68-83`); `safeRun` turns that into `{error}`.
- impact: the task is queued but no action event is written and the per-session counter is not charged; the model sees a failure and re-dispatches (merge keeps one task, audit and limit are wrong).
- action: try/catch the memory write and return `{ dispatched: true, memoryWritten: false }`.
